# Phase 4: Phase 4 – HTMX Desktop UI: Session Dashboard
**Milestones: 7**

Build the desktop web dashboard as server-rendered HTML with HTMX partial swaps, styled after the Hive design system with blue accents. This is the primary operator interface. No client-side framework; xterm.js is the only significant JS loaded.

## Milestone 2: HTMX session card components: status badge, branch name, timestamps; polled via hx-trigger every 2s
Build the session card HTML partial that HTMX polls every 2 seconds. Each card shows session ID, branch name, status badge with colour coding, created/updated timestamps, and a placeholder terminal slot. The card partial is served from a dedicated Express route that returns only the card fragment.

1. Add to `src/web/public/css/components.css` the following card sub-component styles: `.session-card` (extends `.card` with flex column, min-height 180px, position relative), `.session-card__header` (flex row, justify-content space-between, align-items center, padding 0.75rem 1rem, border-bottom 1px solid var(--color-border)), `.session-card__body` (padding 0.75rem 1rem, flex-grow 1), `.session-card__footer` (padding 0.5rem 1rem, border-top 1px solid var(--color-border), flex row gap 0.5rem), `.badge--running` (background var(--color-accent-dim), color var(--color-accent), a pulsing `@keyframes pulse` animation on the dot), `.badge--stopped` (muted colours), `.badge--error` (error colour).
2. Create `src/web/views/partials/session-card.html` as an ETA partial. The root element is `<div class='session-card' id='session-<%= it.id %>' hx-get='/api/sessions/<%= it.id %>/card' hx-trigger='every 2s' hx-swap='outerHTML'>`. Inside render: a header with `<span class='font-mono text-sm'><%= it.branch %></span>` and `<span class='badge badge--<%= it.status %>'><%= it.status %></span>`. In the body render `<p class='text-muted text-xs'>Started <%= it.createdAt %></p>` and `<p class='text-muted text-xs'>Updated <%= it.updatedAt %></p>`. In the footer render `<div class='terminal-slot' id='terminal-<%= it.id %>'></div>` and action buttons placeholder `<div class='card-actions'></div>`.
3. Create `src/web/views/partials/session-grid.html` that loops over `it.sessions` and includes `session-card.html` for each, wrapped in `<div class='session-grid' id='session-grid'>`.

7. Mount the sessions router in `src/web/server.ts` with `app.use('/api', sessionsRouter)`.
8. Verify polling behaviour manually: open `http://localhost:3000` in a browser, open DevTools Network tab, confirm XHR requests to `/api/sessions/:id/card` fire approximately every 2 seconds per visible card.

## Milestone 4: xterm.js terminal panel: loaded lazily per card, WebSocket connected to /ws/terminal/:id, fit addon for resize
Wire an xterm.js terminal into each session card's terminal slot. The terminal is loaded lazily when the user clicks 'Open Terminal' on a card, connects via WebSocket to /ws/terminal/:id established in Phase 3, and uses the FitAddon to fill its container. The session card layout expands inline to show the terminal.

1. Add CSS to `src/web/public/css/components.css` for the terminal panel: `.terminal-panel` (background #000, border-radius 0 0 var(--radius-card) var(--radius-card), overflow hidden, height 0, transition height 0.25s ease), `.terminal-panel.is-open` (height: 320px), `.xterm-container` (width 100%, height 100%), `.session-card.has-terminal` (min-height: 500px).
2. Download xterm.js and its FitAddon to `src/web/public/vendor/`: `xterm.js` (v5.x UMD build), `xterm.css`, `xterm-addon-fit.js`. Add a `scripts.vendor` npm script in `package.json` that uses `node scripts/vendor-assets.js` to copy these from `node_modules/xterm/lib/xterm.js`, `node_modules/xterm/css/xterm.css`, and `node_modules/@xterm/addon-fit/lib/addon-fit.js` into `src/web/public/vendor/`. Add `xterm` and `@xterm/addon-fit` to `devDependencies` in `package.json` and run `npm install`.
3. Create `src/web/public/js/terminal.js` as a plain ES module. Export function `openTerminal(sessionId, containerId)`: create `const term = new Terminal({ fontSize: 13, fontFamily: getComputedStyle(document.documentElement).getPropertyValue('--font-mono'), theme: { background: '#000000', foreground: '#e2e8f0', cursor: '#2563eb' }, cursorBlink: true })`. Create `const fitAddon = new FitAddon.FitAddon()`, call `term.loadAddon(fitAddon)`. Call `term.open(document.getElementById(containerId))`, then `fitAddon.fit()`. Construct `const ws = new WebSocket('ws://' + location.host + '/ws/terminal/' + sessionId)`. Set `ws.binaryType = 'arraybuffer'`. On `ws.onmessage`, call `term.write(new Uint8Array(event.data))`. On `term.onData`, call `ws.send(data)`. Add a `ResizeObserver` on the container element that calls `fitAddon.fit()` and sends `JSON.stringify({ type: 'resize', cols: term.cols, rows: term.rows })` over the WebSocket. Export a `closeTerminal(sessionId)` function that stores open terminals in a `Map<string, {term, ws}>` module-level variable and calls `ws.close()` then `term.dispose()` on the stored instance.
4. Create `src/web/views/partials/terminal-panel.html` rendering `<div class='terminal-panel is-open' id='terminal-panel-<%= it.id %>'><div class='xterm-container' id='xterm-<%= it.id %>'></div></div><script>import('/js/terminal.js').then(m => m.openTerminal('<%= it.id %>', 'xterm-<%= it.id %>'));</script>`.
5. In `src/web/views/partials/session-card.html`, add an 'Open Terminal' button in the `.session-card__footer`: `<button class='btn btn-ghost btn-sm' hx-get='/api/sessions/<%= it.id %>/terminal' hx-target='#terminal-slot-<%= it.id %>' hx-swap='innerHTML' onclick='this.closest(".session-card").classList.add("has-terminal")'>Open Terminal</button>`. Change the terminal slot div to `<div class='terminal-slot' id='terminal-slot-<%= it.id %>'></div>`.
6. In `src/web/routes/sessions.ts`, register `GET /api/sessions/:id/terminal` that renders `partials/terminal-panel.html` with `{ id: req.params.id }`. This returns the HTML fragment that HTMX injects into the terminal slot, which then executes the inline `<script>` to mount xterm.js.
7. In `src/web/views/layout.html`, add in `<head>`: `<link rel='stylesheet' href='/vendor/xterm.css'>`. Do NOT load `xterm.js` or `addon-fit.js` in the `<head>` — they are loaded lazily via the dynamic `import()` in the terminal panel partial. Add `<link rel='modulepreload' href='/js/terminal.js'>` so the browser pre-fetches but does not execute the module.

## Milestone 7: Real-time status badge updates via Server-Sent Events (/api/events stream) replacing polling for status changes
Replace the per-card 2-second `hx-trigger='every 2s'` polling with a Server-Sent Events stream at /api/events. The SSE stream pushes session status change events; an HTMX `hx-ext='sse'` listener on each card swaps in the updated status badge HTML fragment without refetching the whole card. Card polling is removed to reduce server load.

1. Create `src/web/services/event-bus.ts` exporting a singleton `EventBus` class. The class maintains a `Set<(event: SseEvent) => void>` of subscriber callbacks. Export `type SseEvent = { sessionId: string; type: 'status' | 'created' | 'deleted'; status?: string; html?: string }`. Export methods `subscribe(cb)` returning an unsubscribe function, and `publish(event: SseEvent)` that calls all registered callbacks. Export `eventBus = new EventBus()` as a module-level singleton.
2. In `src/web/services/session-service.ts` (Phase 2 adapter), import `eventBus` from `event-bus.ts`. After any status transition (session created, stopped, killed, errored), call `eventBus.publish({ sessionId: session.id, type: 'status', status: session.status })`. After `createSession` succeeds call `eventBus.publish({ sessionId, type: 'created' })`. After delete call `eventBus.publish({ sessionId, type: 'deleted' })`.
3. Create `src/web/routes/events.ts` exporting an Express Router. Register `GET /api/events` with a handler that: sets headers `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no` (to disable nginx buffering in Azure). Calls `res.flushHeaders()`. Subscribes to `eventBus` with a callback that writes `data: ${JSON.stringify(event)}\n\n` and calls `res.flush()` (requires `compression` middleware to be bypassed for this route). Stores the unsubscribe function and calls it on `req.on('close', unsubscribe)`. Sends a keepalive comment `: keepalive\n\n` every 25 seconds using `setInterval`, clearing it on close.
