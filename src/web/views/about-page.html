What is Orcha?

A terminal session manager for AI-assisted development

Orcha is a self-hosted dashboard for orchestrating multiple Claude Code terminal sessions. It lets teams run parallel AI coding sessions across repositories, each with scoped credentials and isolated worktrees.

The name comes from orchestrata — coordinating many agents working together.

Architecture

Server-rendered, no SPA framework

Orcha uses a deliberately simple architecture — server-rendered HTML enhanced with HTMX for interactivity. There's no React, no Vue, no build-time JS bundling for the frontend.

Request flow

  1. Browser requests a page (e.g. /presets)
  2. Express route renders an ETA template into the layout shell
  3. Page loads with skeleton placeholders
  4. HTMX fires hx-trigger="load" requests to /api/* endpoints
  5. API routes return HTML partials that swap into the page
  6. User actions (create, edit, delete) POST via HTMX, response triggers a list refresh

Terminal sessions

Each session spawns a PTY process via node-pty. The terminal is streamed to the browser over WebSocket using xterm.js. Sessions run in isolated git worktrees so multiple sessions can target the same repo without conflicts.

Design Decisions

Why no SPA?

HTMX provides the interactivity of a single-page app without shipping a JS framework to the browser. Pages load fast, the server is the source of truth, and there's no client-side state to synchronize.

Why SQLite?

Orcha is designed for single-machine deployment. SQLite via better-sqlite3 gives us a fully synchronous, zero-config, embedded database with no separate process to manage. WAL mode handles concurrent reads.

Why git worktrees?

Each session gets an isolated checkout via git worktree add. This lets multiple sessions work on the same repo on different branches without filesystem conflicts — and cleanup is a single git worktree remove.

Why scoped credentials?

AI agents shouldn't have permanent access to cloud resources. Orcha provisions credentials when a session starts and revokes them when it ends. If a session fails or is cancelled, cleanup runs automatically.
